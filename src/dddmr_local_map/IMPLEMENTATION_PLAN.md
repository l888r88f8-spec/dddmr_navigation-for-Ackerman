# 完整点云局部地图接入 MPPI

目标：让现有 MPPI 使用含地面的完整去畸变点云，通过局部地形支撑与三维车体碰撞判断通行。保留现有全局 PCD、Hybrid A*、dGraph 和默认点云后端。GNSS／高德全局无图导航不在本次范围。

实施顺序：

1. **冻结基线。** 在 `feat/local-occupancy-mppi` 分支开发，保存并核对用户原有三处修改，不启动实车控制。
2. **独立建图。** 新增 `dddmr_local_map`，订阅 `/lio_sam/deskew/cloud_deskewed`，以采集时刻 TF 转入 `odom`。实现固定容量循环体素、射线概率更新、未知状态和增量膨胀，每帧发布不可变快照。
3. **缓存地形。** 从真实命中点建立局部多层支撑面，检查四轮支撑、坡度、台阶、落差与完整车体姿态；地面保留在地图中，按支撑语义参与判断。
4. **接入 MPPI。** 新后端每周期固定同一地图版本和坐标变换，逐姿态检查候选，并复验最终加权序列；评分和 RViz 共用投影姿态。地图超时、未知支撑或无效几何均拒绝命令。
5. **旁路验证。** 运行核心、轨迹、参数覆盖与原有回归测试，用隔离 ROS 域验证 shadow 节点输入、TF、占据显示和输入超时。
6. **性能与部署验收。** 在 Orin NX 上测量有效查询的耗时分布，优化重复计算；随后用完整导航数据回放验证端到端控制周期和实际场景。

当前软件实现与前五步验证已完成；性能结果和剩余验收应结合最新测量记录查看。合成测试不能替代完整导航链路验收。

实车参数已记录在 [VEHICLE_GEOMETRY.md](VEHICLE_GEOMETRY.md)：轴距 0.460 m、轮距 0.550 m、base 高约 0.220 m、底盘离地 0.120 m。附件最高点尚未测量，因此新配置故意不填写 `body_max`，新控制后端保持几何未就绪。前后悬伸量仍需核对。

部署前尚需完成：

- 测量包含雷达、支架的完整刚性包络，核对 base 高度和前后悬伸。
- 用含完整去畸变云、TF、里程计的同一段数据对比两个后端；现有原始雷达 bag 不能直接替代。
- 验证整轮控制 P95/P99、50 ms 预算和 15 Hz 周期；查询耗时乘以姿态数量只能用于估算。
- 检查传感器能否观测轮胎接触区域，完成平地、坡脚／坡顶、低障碍、悬空物和落差场景验收。

构建、shadow 启动与后端参数见 [README.md](README.md)。
